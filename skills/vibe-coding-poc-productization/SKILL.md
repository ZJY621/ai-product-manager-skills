# Vibe Coding POC 产品化

## 使用场景

当需要把一个产品想法快速变成可演示 Demo、HTML 网站、内部工具或评测平台 POC 时使用。

## 核心原则

Vibe Coding 不是随便让 AI 写页面，而是把模糊想法结构化成可执行需求。

```text
业务痛点 -> 产品目标 -> 用户流程 -> 功能模块 -> 数据结构 -> 页面结构 -> 验收标准 -> 迭代反馈
```

## 输入信息

开始前收集：

- 产品解决什么问题
- 用户是谁
- 核心使用流程
- 必须有的功能
- 暂不做的功能
- 数据字段
- 页面结构
- 交互状态
- 视觉风格
- 验收标准

## 工作流

1. 定义 POC 目标  
   明确是验证流程、验证价值、做面试展示，还是内部提效。

2. 收敛 MVP 功能  
   只做最小闭环，避免一次性做完整平台。

3. 输出 AI 可执行 PRD  
   写清页面、模块、字段、流程、状态、验收。

4. 选择实现形态  
   HTML 单页、React 应用、本地工具、脚本、静态网站。

5. 生成原型  
   使用 Claude Code、Codex、Cursor 等工具实现。

6. 验收和修改  
   按功能、视觉、交互、移动端、数据展示逐项检查。

7. 沉淀复用  
   将流程、组件、字段、Prompt、坑点沉淀为 Skill 或模板。

## 输出模板

```markdown
## POC 目标

## 用户与场景

## MVP 范围
- 做：
- 不做：

## 核心流程

## 功能模块

## 数据字段

## 页面结构

## 交互状态

## 视觉风格

## 验收标准

## 后续迭代
```

## 常见 POC 类型

- 项目介绍网站
- 公司面试速览页
- Agent 评测平台
- Badcase 管理工具
- 数据源管理后台
- 简历/作品集网站
- 竞品分析 Dashboard

## 验收标准

一个合格 POC 至少要满足：

- 业务流程能跑通
- 用户一眼知道这个工具解决什么问题
- 核心字段和状态完整
- 页面能真实演示
- 后续能继续扩展

## 面试口径

“我用 Vibe Coding 不是为了炫技，而是把产品想法快速变成可验证的 Demo。先用 PRD 把流程、字段、页面和验收标准写清楚，再让 AI 生成原型，最后通过实际演示验证方案是否成立。”
