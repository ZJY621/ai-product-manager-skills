# RAG 与数据源边界设计

## 使用场景

当 AI 产品需要调用知识库、业务数据、文档、数据库或外部 API，并且要求回答可信、可溯源、可评测时使用。

## 核心原则

不要把所有数据都丢给模型。要先定义：

- 每类数据的作用
- 哪些节点可以调用
- 能否作为最终依据
- 如何召回
- 如何溯源
- 召回不足时如何兜底

## 数据源分层

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 检索过滤层 | 快速缩小候选范围 | 摘要库、标签库、索引库 |
| 事实依据层 | 支撑客观结论 | 原文、公告、合同、订单、数据库查询结果 |
| 分析逻辑层 | 支撑解释和观点 | 研报、分析报告、历史案例、业务规则 |
| 结构化数据层 | 支撑计算和指标 | 行情、指标、用户行为、交易数据 |
| 画像关系层 | 支撑关联和推荐 | 公司资料、商品属性、用户标签、概念关系 |

## 工作流

1. 列出数据源  
   包括名称、来源、更新频率、字段、权限、可靠性。

2. 定义数据作用  
   区分用于检索、排序、推理、展示、最终依据。

3. 绑定 Agent 节点  
   明确哪个 Agent 调用哪些数据源。

4. 设计召回策略  
   关键词、向量、混合检索、Rerank、Top-K、时间过滤、热度排序。

5. 设计溯源规则  
   最终结论必须能回到原文 ID、数据表、查询结果或业务规则。

6. 设计兜底策略  
   召回为空、召回不足、依据冲突、数据过期、权限不足时如何处理。

7. 定义评测指标  
   召回准确率、来源可溯率、依据一致性、幻觉率、权限命中率。

## 输出模板

```markdown
## 数据源清单
| 数据源 | 来源 | 作用 | 调用节点 | 是否最终依据 | 更新频率 | 风险 |

## 数据调用链路

## 检索召回策略

## 溯源规则

## 兜底策略

## 评测指标
```

## 示例口径

“摘要库只负责第一层检索和排序，不作为最终生成依据；最终 Summary 必须回到原文块、研报块或结构化查询结果，并绑定来源 ID。召回不足时不让模型自由补全，而是触发兜底或提示信息不足。”

## 风险提醒

以下情况必须谨慎：

- 模型基于预训练知识补结论
- 摘要替代原文作为最终依据
- 权限不同的用户看到相同数据
- 数据过期但未提示
- 多个来源结论冲突但未处理
