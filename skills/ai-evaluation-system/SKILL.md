# AI 产品评测体系

## 使用场景

当用户需要回答或设计：

- AI 效果怎么评估
- 评测体系怎么搭建
- 测试集怎么构建
- Badcase 怎么进入下一轮迭代
- 模型/Prompt/链路改了怎么验证是否变好

使用本 Skill。

## 核心原则

AI 产品不是只做测试，而是做评测。评测要能定位问题节点。

```text
业务场景 -> 测试集 -> 预期结果 -> 实际结果 -> 指标计算 -> Badcase 归因 -> 版本回归
```

## 评测集字段

建议字段：

- Query 原文
- 子问句
- 业务场景
- OOD 标记
- 多意图标记
- 预期路由
- 预期槽位
- 预期数据源/召回来源
- 预期输出结构
- 标准答案或判断标准
- 实际结果
- 结果状态
- Badcase 标签
- 修复版本

## 常用指标

| 指标 | 说明 | 对应节点 |
| --- | --- | --- |
| 路由准确率 | 是否走对任务路径 | Planner/Router |
| 槽位准确率 | 时间、主体、维度、约束是否抽对 | Planner/Parser |
| 召回准确率 | 是否找到正确材料或数据 | RAG/Tool |
| 依据一致性 | 输出结论是否被材料支撑 | Summary |
| 结构一致性 | 输出格式是否稳定 | Summary |
| OOD 拒答准确率 | 越界问题是否正确拒答 | Safety |
| 响应时间 | 是否满足体验要求 | 全链路 |
| 用户反馈指标 | 点赞、点踩、追问、留存、转化 | 产品效果 |

## 工作流

1. 拆业务场景  
   列出核心路径、边界问题、异常问题、多意图问题。

2. 建初始评测集  
   从真实 Query、业务专家、历史案例、竞品、合成样本中收集。

3. 标注预期结果  
   每条样本都要能判断对错，不只存 Query。

4. 定义指标  
   指标必须对应可优化节点。

5. 跑评测  
   比对实际结果和预期结果。

6. 做 Badcase 归因  
   标出问题属于路由、槽位、召回、依据、结构、合规等。

7. 回归验证  
   每次 Prompt、规则、模型、链路变更后跑同一批评测集。

## 输出模板

```markdown
## 评测目标

## 业务场景拆解

## 评测集字段设计

## 评测指标
| 指标 | 定义 | 计算方式 | 对应节点 |

## Badcase 标签

## 回归测试流程

## 面试表达
```

## 面试口径

“我做评测不是只看最后回答好不好，而是把一个 Query 的预期路由、槽位、召回来源和输出结构都标出来。实际结果和预期一对比，就能知道问题大概率出在 Planner、检索、子 Agent 还是 Summary。”
